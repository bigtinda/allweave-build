# 阶段性遗留问题

本目录按迁移阶段记录未完成、未验收或已知缺陷。目标不是留档了事，而是让问题在具备修复条件时被及时处理。

## 规则

1. 每个问题必须有稳定 ID，格式 `M<阶段>-<序号>`。
2. 必须写清：现象、位置、当前规避、修复条件、修复动作、验收方式。
3. 条件满足时，在当次开发中直接修复，并把状态改为 `resolved`，补充提交号或验证结果；不要另开无主任务。
4. 条件不满足时保持 `open`，由阶段负责人每个阶段结束时复查一次。
5. 阻断默认引擎、数据迁移或安全边界的问题标记 `blocker`，优先处理。
6. 本目录不复制架构设计；设计见 `docs/ARCHITECTURE.md`。

## 状态

- `open`：确认存在，尚未修复。
- `in-progress`：已开始处理。
- `blocked`：依赖外部条件或后续阶段。
- `resolved`：已修复并验证。
- `wontfix`：明确不做，需写原因。
